# [Investigation] カメラ権限エラー表示の汎用化によるデバッグ性・UX 影響の確認

- **対応 GitHub Issue**: GitHub Issue #238
- **関連 PR**: PR #198
- **ステータス**: 完了 (Closed)
- **対象ソース**: `src/hooks/cameraCapture/useCameraPermission.ts`, `src/components/screens/camera/CameraView.tsx`, `src/utils/openAppSettings.ts`

## 目的・概要
PR #198 で導入されたカメラ権限エラー表示の汎用メッセージ化に伴い、ユーザー向けのアクション案内（設定画面への誘導等）の分かりやすさ（UX）およびエラー監視・開発時ログのデバッグ性が十分に維持されているかを調査・確認した記録です。

---

## 調査・確認結果

### 1. ユーザー向けエラー案内（Actionable UX）の確認

| 状態・シナリオ | 画面 / ダイアログ表示 | アクション案内（導線） | UX 評価 |
|---|---|---|---|
| **初回または未許可** (`needs_request`) | `撮影を始めるにはカメラ権限が必要です` (カード表示) | 「カメラを許可する」ボタンタップで OS 権限プロンプト表示 | 直感的で問題なし |
| **権限拒否 / ブロック** (`denied` / `canAskAgain === false`) | `カメラ権限がオフになっています` (全画面カード) | 「設定を開く」ボタンタップで OS 設定アプリへ即座に遷移 (`Linking.openSettings`) | 復帰導線が常時提供されており良好 |
| **権限リクエスト失敗 (camera関連エラー)** | `Alert.alert('カメラエラー', 'カメラの初期化に失敗しました。Expo Goを再起動するか、開発ビルドを使用してください。')` | 再起動または開発ビルドの利用を明示 | 対処法が具体的で良好 |
| **権限リクエスト失敗 (permission関連エラー)** | `Alert.alert('権限エラー', 'カメラ権限が拒否されました。アプリの設定から権限を許可してください。')` | アプリ設定からの許可を案内 | 直感的で問題なし |
| **権限リクエスト失敗 (その他汎用例外)** | `Alert.alert('エラー', '権限確認中にエラーが発生しました。')` | 画面上の「カメラを許可する」「設定を開く」導線が維持 | 生エラーを隠蔽しつつ安全に案内 |
| **設定アプリオープン失敗** | `Alert.alert('設定を開けませんでした', 'アプリの設定画面からカメラ権限を許可してください。')` | 手動での設定アプリ起動を案内 | フォールバック完備 |

**結論**: PR #198 におけるアラート文言の汎用化は、内部ファイルパスや生例外のユーザー露出を防ぐ正当なセキュリティ対策であり、画面上の `PermissionDeniedView` による「設定を開く」常設ボタンや、シナリオ別（カメラ初期化失敗・権限拒否）の個別メッセージ分岐により、Actionable UX は十分に担保されています。

### 2. デバッグログおよび例外追跡性（Sentry連携）の確認

- **内部ログ出力**:
  `useCameraPermission.ts` の `handlePermissionError` では、`console.error('Permission request failed:', sanitizeLogObject(error))` を実行。
  - `sanitizeLogObject` により、ローカルファイルパス（`/var/mobile/...` や `/data/user/0/...`）などの機密情報のみがマスクされ、エラー名や根本原因（スタックトレース等）は開発者コンソールへ保持されます。
- **将来の Sentry 導入（Issue #51）への影響**:
  - 生の例外が完全に握り潰される（silent catch）ことはなく、`console.error` にコンテキストが残るため、Sentry の `captureException` または breadcrumb ロギングと直結可能です。
  - 機密情報がマスクされているため、Sentry 送信時の PII（個人情報）漏洩リスクを低減する効果もあります。

---

## 結論・提言
- 現行のカメラ権限ハンドリングおよび UI/UX は、セキュリティ（例外隠蔽・PII保護）とユーザビリティ（設定アプリへの明示的導線）を高水準で両立しており、**追加のコード変更は不要**と判断します。
- 将来 Sentry（Issue #51）を導入する際は、`handlePermissionError` に Sentry イベント送信フックを追加するだけで問題なく統合可能です。
