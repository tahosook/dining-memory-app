# [Investigation] 撮影写真の保存時圧縮・リサイズ機構の検討

- **内部ドキュメントID**: issue-03
- **対応 GitHub Issue**: GitHub Issue #75
- **GitHub Issue 状態**: OPEN（GitHub 側未クローズ）
- **ドキュメント内進捗ステータス**: 調査・評価完了（実装 Issue #86, #87, #88 へ切り出し・マージ済み）
- **実測評価レポート**: [docs/notes/photo-compression-evaluation-issue-75.md](../notes/photo-compression-evaluation-issue-75.md)
- **後続実装 PR**: PR #102（GitHub Issue #86, #87: ネイティブリサイズ・サムネイル世代分離）、PR #105（GitHub Issue #88: 孤立写真回収とライフサイクル保護）

## 目的
撮影写真の保存容量を削減しつつ、食事記録として十分な画質を維持できる保存仕様を検討・決定する。

## 背景・現状
現在、カメラで撮影された写真は `persistPhotoToStablePath`（`src/media/photoStorage.ts`）において、オリジナルのカメラ解像度・ファイルサイズのまま端末のドキュメントディレクトリへコピー保存されています。スマートフォンのカメラ写真は 1 枚あたり 5〜10MB 以上のサイズになるため、食事記録の蓄積に伴い端末ストレージやバックアップ容量を圧迫する懸念があります。
プロジェクトには既に画像リサイズライブラリ `@bam.tech/react-native-image-resizer` が導入済み（`package.json` に記載、`src/media/mealThumbnail.ts` でサムネイル生成に使用）ですが、メイン写真の保存処理では未使用となっています。
本Issueは、新規ライブラリ選定を行うのではなく既存の resizer 依存を活用する前提に立ちつつ、具体的な解像度や圧縮率を十分な事前評価なしに決め打ち実装するリスク（画質の劣化、EXIF消失、バックアップ・表示処理との不整合など）を防ぐため、実測と評価を行って適切な保存仕様を決定します。

## 実施内容
### 1. 現行処理および既存 resizer の調査
以下の既存機能・実装の相互関係と責務を確認する：
- 既存依存 `@bam.tech/react-native-image-resizer` の利用状況・呼び出し箇所の確認（`src/media/mealThumbnail.ts` での利用方法）
- メイン写真保存（`src/media/photoStorage.ts`）で現在 resizer が適用されていない理由・前提の確認
- `writePhotoExifToJpeg`（EXIF メタデータの書き込み）との順序・連携
- `tests/photoStorage.test.ts`, `tests/captureSaveWorkflow.test.ts`
- バックアップ・インポート処理（ZIP アーカイブ作成・展開時の写真整合性）
- 写真表示処理（RecordsScreen, SearchScreen, MealDetailScreen での画像読み込み）

### 2. 既存 resizer を前提とした実測・評価
実際の撮影画像をサンプルとして用い、新規選定ではなく既存 resizer を使用する前提で以下の項目を評価する：
- 元画像の解像度
- 元画像のファイルサイズ
- リサイズ後の解像度
- JPEG品質ごとのファイルサイズ
- 写真表示時の画質
- EXIF保持状況
- バックアップ容量への影響
- 処理時間
- リサイズ失敗時の挙動
※ 長辺ピクセル数（例: 1920px など）や JPEG 品質（例: 80〜85% など）の具体値は、この評価結果を踏まえて決定する。

### 3. 重要な設計条件の整理
- 写真保存の失敗によって食事記録そのものが壊れないこと。
- リサイズ・圧縮処理失敗時の安全なフォールバックを検討する。
- 既存写真との互換性を壊さないこと。
- バックアップ／インポート処理への影響を確認する。
- EXIFの扱いを明確にする。
- サムネイル生成とメイン写真保存の責務を混同しないこと。

## 今回やらないこと（Non-goals / Out of scope）
- 評価や合意を経ずに、特定の解像度やJPEG品質をコードへ直接実装すること
- 新規の画像リサイズライブラリ選定（既存の `@bam.tech/react-native-image-resizer` を活用前提とする）
- サムネイル生成処理（`mealThumbnail.ts`）の責務変更
- 既存写真やバックアップ形式の破壊的変更
