# MediaPipe 食品分類 Golden Test Set v2 仕様書

## 1. 概要と目的

本ドキュメントは、`dining-memory-app` の MediaPipe 食品分類モデル（`meal-input-assist.task`）の評価・回帰テスト基盤として構築された **Golden Test Set v2 (106枚)** の仕様、選定根拠、制約事項、および運用方法を定めたものです。

### 1.1 背景と位置付け
- **旧 Golden Test Set (7枚) の役割と課題**:
  - 1クラス1枚（全7クラス・計7枚）で構成され、主要代表サンプルに対する回帰ガード（Regression Guard Check）としては機能するものの、サンプルサイズが小さすぎる（1サンプルの誤判定で正解率が $\pm 14.3\%$ 変動）。
  - また、9クラス中 2クラス（`noodles`, `stir_fry`）が含まれていなかった。
- **Golden Test Set v2 の位置付け**:
  - 本データセットは、**完全独立のブラインド評価セットではなく、過去の validation・test・モデル選定履歴を持つ画像プールから人間の全数目視確認によって再編された「拡張回帰テストセット（Comprehensive Regression & Benchmarking Set）」** です。
  - 原則として 9クラス × 20枚 ＝ 180枚 を目標としましたが、「品質を犠牲にして枚数を満たしてはならない」「目視確認できていない画像・判定が曖昧な画像を混入させない」「学習データとの重複を起こさない」という原則を厳格に適用し、**確定した106枚** で構成されています。

---

## 2. 選定プロセスと監査結果

### 2.1 母集団の選定と監査 (Phase 1)
- リポジトリ内の全画像（約3,391枚）から、学習用スプリット（`train`）として使用された実績のある349枚を完全に特定・隔離。
- 学習に使用されていない評価候補プール（299枚）を抽出。
- 候補プールと学習セットの間で SHA-256 完全重複ゼロ、aHash 加工類似ゼロを確認。

### 2.2 人間による全数目視確認 (Phase 2 & Phase 3)
- 候補299枚すべてについて、人間レビュアーによるWebコンソールおよびコンタクトシートを用いた目視確認を実施。
- **目視確認の内訳**:
  - `ok`（暫定ラベルが正しい）: 146件 (48.8%)
  - `relabel`（人間が正しいラベルに修正）: 91件 (30.4%)
  - `exclude`（対象外・画質不良・判定不能で除外）: 36件 (12.0%)
  - `ambiguous`（複数料理の混在などで除外）: 26件 (8.7%)
- **AI擬似ラベルの誤認傾向の是正**:
  - 自動生成されていた擬似ラベルでは `simmered_dish`（煮物）、`fried_dish`（揚げ物）、`stir_fry`（炒め物）と判定されていたものの多くが、実際には肉料理（ステーキ、角煮、ソテー）や魚料理であったことが目視確認により判明。
  - 正しく `meat_dish` や `fish_dish` に修正された結果、高信頼な正解ラベルが確定。
- **連写ペアの重複排除**:
  - 撮影時間差30分以内の連写ペアについて、評価の独立性（iid）を担保するため 2件（CAND_036, CAND_045）を除外。

## 4. 厳格な監査に基づく制約事項 (Limitations)

### 4.1 旧 Golden 7枚との関係
- 旧 Golden 7枚（原本: `state/mediapipe-dataset/golden_eval/test/`）のうち、**v2 に継承されたのは目視で `ok` だった 6枚** です。
- 残る 1枚（`CAND_204`: `034_meshi_...` / `simmered_dish`）は、人間による目視確認において明示的に `ambiguous`（判定曖昧）と判定されたため、ルール7に従い **v2 から除外** されました。
- 旧 Golden 7枚の原本自体は一切変更・削除されておらず、現行の Promotion Gate（`REQUIRED_TEST_SET_SIZE="7"`）の回帰テスト用として完全に維持されています。

### 4.2 データの独立性と過去の使用履歴
- 本データセット（106枚）は完全独立のブラインドテストセットではありません。
- 過去の使用履歴の分類結果：
  - `train_exposed`: **0枚** (0.0%)
  - `model_selection_exposed`: **6枚** (5.7%) — 旧 Golden 継承画像（モデル昇格判定に使用）
  - `validation_exposed`: **16枚** (15.1%) — 過去の学習時の validation split
  - `test_exposed`: **84枚** (79.2%) — 過去のブラインド監査・テスト split
- 学習349枚との SHA-256 重複が 0件 であることは、**「学習画像との完全一致が確認されなかったこと」** を意味するものであり、過去の評価や検証への露出が皆無であることを証明するものではありません。

### 4.3 クラス間不均衡とモデル評価の注意点
- クラスごとのサンプル数は 3枚（`other_or_exclude`）から 20枚（`curry_rice`, `fish_dish`, `meat_dish`）まで不均衡です。
- 特に `stir_fry`（炒め物）は 4サンプル中 Top-1 正解が 0件（0.0%）ですが、これは少数サンプルの実測結果であり、モデルの炒め物クラス全体の網羅的性能を確定するものではありません。
- モデル品質の評価にあたっては、全体正解率だけでなく、クラス別の Precision / Recall / F1 を併せて確認することが必須です。

### 4.4 Git 管理外データと再現可能性
- 実画像（JPEG）、マニフェスト（CSV/JSONL）、および評価結果 JSON は、リポジトリ肥大化防止ポリシーに従い **Git 管理外（`.gitignore`）** です。
- 単体テスト（`scripts/tests/test_verify_golden_dataset_v2.py`）は合成モックにより CI 上でも 100% 独立して実行可能ですが、実データを用いた 106枚の完全検証（`scripts/verify-golden-dataset-v2.py`）を第三者が実行するには、ローカルまたはセキュア環境に `state/mediapipe-dataset/golden_eval_v2/` の実データを配置する必要があります。

## 5. データセット構造とマニフェスト仕様

Golden Test Set v2 は、ローカル環境の `state/mediapipe-dataset/golden_eval_v2/` 配下に構築されます。

```text
state/mediapipe-dataset/golden_eval_v2/
├── labels.txt              # 全9クラスのラベル一覧
├── manifest.csv            # カンマ区切りのマニフェスト
├── manifest.jsonl          # 詳細メタデータ（JSONL形式）
└── test/                   # クラス別テスト画像ディレクトリ（計106枚）
    ├── curry_rice/         # 20枚
    ├── drink/              # 17枚
    ├── fish_dish/          # 20枚
    ├── fried_dish/         # 4枚
    ├── meat_dish/          # 20枚
    ├── noodles/            # 11枚
    ├── other_or_exclude/   # 3枚
    ├── simmered_dish/      # 7枚
    └── stir_fry/           # 4枚
```

### マニフェストのメタデータ項目
各画像レコードには以下のメタデータが記録されています：
- `golden_id`: 一意のGolden ID（`GOLDEN_V2_001` 〜 `GOLDEN_V2_106`）
- `candidate_id`: レビュー時の候補ID（`CAND_001` 〜 `CAND_299`）
- `confirmed_label`: 人間が確定した正解クラス名
- `provisional_label`: レビュー前の暫定クラス名
- `human_judgment`: 人間レビュー結果（`ok` または `relabel`）
- `sha256`: 画像の SHA-256 チェックサム
- `filename`: 元ファイル名
- `rel_path_source`: リポジトリ内での元画像パス
- `source_pool`: 抽出元プール（`batch250_test`, `batch250_val`, `gemini_audit_sample_70`, `gemini_audit_sample_A`, `golden_eval_7`）
- `selection_reason`: 選定理由（`exhausted_available_pool`, `stratified_deterministic_sampling`, `benchmark_champion_preservation`）
- `reviewed_by`: レビュアー名（`human_evaluator`）
- `reviewed_at`: レビュー日（`2026-10-12`）
- `is_legacy_golden_7`: 旧 Golden 7枚に含まれていたかどうかのフラグ（True: 6枚, False: 100枚）

## 6. 自動検証とテスト

### 6.1 自動検証スクリプト
ローカルにデータが存在する環境において、以下のコマンドでデータセットの整合性を検証できます。

```bash
python3 scripts/verify-golden-dataset-v2.py
```

**検証項目**:
1. マニフェスト整合性（JSONL / CSV 各106件の一致）
2. 実画像存在確認（`test/<class>/` 配下の106ファイル）
3. SHA-256 ハッシュの 100% 一致
4. JPEG バイナリヘッダ（SOI `\xff\xd8`）およびフッタ（EOI `\xff\xd9`）による破損検査
5. 訓練スプリット（349枚）との SHA-256 重複ゼロ確認
6. 定義外不正ラベルの排除
7. 各クラス上限（20枚以下）の確認

### 6.2 単体テスト (CI 実行可能)
合成モックを用いたテストスイートは、外部データに依存せず実行可能です。

```bash
python3 -m unittest scripts.tests.test_verify_golden_dataset_v2
```
